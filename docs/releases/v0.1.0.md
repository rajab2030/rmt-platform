# RMT v0.1.0 — release notes (draft)

**Status: draft.** The tag and GitHub release will be created from `master`
after the public-readiness changes are merged and the owner approves these
notes. The date is set at tagging.

The first versioned release of RMT: policy checks, approval holds, and
execution evidence for actions proposed by AI agents and automation. It
packages the capabilities recorded in
[`docs/RMT_CAPABILITIES_EVIDENCE.md`](../RMT_CAPABILITIES_EVIDENCE.md) and
adds a one-command local trial.

## Try it

```bash
git clone https://github.com/rajab2030/rmt-platform.git
cd rmt-platform
docker compose run --rm showcase
```

See the [quickstart guide](../../quickstart/README.md).

## What works

- **One governed lifecycle** for every consequential action: Understand →
  Decide → Govern → Authorize → Execute → Verify → Learn. Blocked, denied,
  held or unauthorized actions never reach an execution adapter. The Core that
  implements it is frozen and covered by its own test suite.
- **Agent Governance Gateway** (RMT-CAP-05 to CAP-08): single-use grants scoped
  to an operation and target, a side-effect-free preview of the policy and risk
  decision, approval holds, durable grants, and an
  [integration guide](../operations/AGENT_API.md). The Git-tag domain
  (CAP-06) needs only Git, which is what the quickstart uses.
- **Evidence**: authorization, approval, audit, trace and verification records
  linked by stable IDs; atomic writes that survive a hard kill; startup
  reconciliation. **Signed evidence export** (CAP-11) with an offline
  verifier.
- **Governed Operations Console** (CAP-09): an evidence viewer and approval
  queue that approves and rejects through the existing governed endpoint.
- **Claude Code command governance** (CAP-10): a `PreToolUse` hook that holds
  risky shell commands for a human decision, with evidence-only reviews.
  [Standalone install guide](../../tools/claude-code-guard/README.md).
- **Homelab domain** (CAP-01, CAP-03, CAP-04): observation, remediation and a
  continuous operational loop for Docker services. This is the platform's
  original proving ground.
- **Operations**: operator bearer-token authentication (the app refuses to
  start when auth is on but unconfigured), optional separation of duties,
  rate limiting, retention, `/metrics`, held-action alerts, and a CI gate that
  runs the full backend suite.

## Out of scope, and known limits

- **Trusted-operator environments only.** Operators share bearer tokens;
  there is no multi-operator identity or RBAC. RMT isn't a defence against
  someone who controls the host.
- **Only what goes through RMT is governed.** Host access and operations
  outside the gateway remain outside the boundary.
- **The quickstart is a demo:** authentication off, one `local-dev` identity
  for granting, proposing and approving, and evidence deleted by
  `docker compose down`. It doesn't demonstrate independent approvers.
- **Approval depends on policy**; not every action needs a human.
- **No general exactly-once execution**, no high availability, no automatic
  rollback (a safe failure is recorded, not reverted).
- **Unapproved Core holds expire** after 300 seconds.
- **The Claude Code guard fails open** when the backend is unreachable,
  including while a command waits for a decision. It covers only its listed
  patterns, and its holds don't expire.
- **Poor fit** for sub-second paths, high-throughput fan-out, or actions with
  no observable outcome.

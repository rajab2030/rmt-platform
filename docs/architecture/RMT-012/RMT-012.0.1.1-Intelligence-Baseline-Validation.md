# RMT-012.0.1.1 Intelligence Baseline Validation

## Status

Validation in progress

## Observed Issue

The Intelligence endpoint `/intelligence/health` returns duplicated issues for the same container components.

Example:

- uptime-kuma repeated multiple times
- dozzle repeated multiple times
- portainer repeated multiple times

## Root Cause

The Intelligence layer consumes recent historical metrics instead of current component state.

Current flow:

Observability Storage
        |
        |
Recent Metrics (historical rows)
        |
        |
Intelligence Rules
        |
        |
Health Evaluation


## Architectural Decision

Intelligence should evaluate current component state, while historical metrics remain available for future trend analysis.

Target flow:

Observability Storage
        |
        |
Observability Service
        |
        |
Current Component State
        |
        |
Intelligence Core


## Planned Change

Introduce a current state retrieval layer:

get_current_container_metrics()

The function will return the latest metric record per container.

## Validation Criteria

The endpoint:

GET /intelligence/health

must return:

- One health evaluation per component
- No duplicate findings caused by historical records
- Stable health score

# منصة RMT

[English](README.md) · **العربية**

> هذه ترجمة للـ README الإنجليزي. عند أي اختلاف، النسخة الإنجليزية هي المرجع.

**فحص السياسات، وتعليق الموافقة، وأدلة التنفيذ لأفعال وكلاء الذكاء الاصطناعي.**

## المشكلة

وكيل ذكاء اصطناعي يريد تنفيذ فعل خطِر: حذف وسم (tag) في Git، أو إعادة تشغيل
خدمة، أو تشغيل `git push --force`. **من يقرّر؟** وبعد التنفيذ، ما الدليل على
من سمح بذلك، وماذا حدث فعلًا؟

## الجواب في ثلاثة أسطر

1. **فحص السياسة والمخاطر (Policy check):** كل فعل يُقترح عبر RMT يُفحص
   ويُصنَّف قبل أن يصل إلى أي منفّذ. يمكن معاينة القرار المتوقع مسبقًا دون أي أثر جانبي.
2. **تعليق الموافقة (Approval hold):** الأفعال التي تتطلب موافقة تُعلَّق، ولا
   يُنفَّذ شيء حتى يوافق مشغّل موثَّق.
3. **أدلة التنفيذ (Execution evidence):** كل قرار وتنفيذ وتحقق يُسجَّل في سجل
   أدلة مترابط يمكن تصديره وتوقيعه والتحقق منه دون اتصال.

## جرّبها خلال دقيقتين

المتطلبات: Docker مع Compose v2 فقط.

```bash
git clone https://github.com/rajab2030/rmt-platform.git
cd rmt-platform
docker compose run --rm showcase
```

يشغّل هذا خادم RMT محليًا (على `127.0.0.1` فقط) ومستودع Git مؤقتًا داخل
الحاوية، ثم يشغّل عميل العرض الذي يمر بالمراحل الخمس. لا يتطلب أي أسرار أو
نموذج لغوي (LLM). عند تعليق فعل ما، اضغط Enter للموافقة بصفتك المشغّل.

الأمر `docker compose down` يوقف التجربة ويحذف كل الأدلة.
التفاصيل واستكشاف الأخطاء: [دليل التشغيل السريع](quickstart/README.md).
للتشغيل اليدوي دون Docker، راجع [دليل العرض](tools/rmt-showcase-agent/README.md).

## ما الذي لا تضمنه هذه التجربة (بصراحة)

- **بيئة مشغّل موثوق:** RMT مصمَّمة لبيئات يكون فيها المشغّل موثوقًا، وليست
  حماية ضد مشغّل خبيث.
- **بيانات اعتماد واحدة:** التجربة تستخدم مشغّلًا واحدًا للمنح والاقتراح
  والموافقة، مع تعطيل المصادقة محليًا. هذا **ليس** عرضًا لهويات موافقين مستقلين.
- **ما يمر خارج البوابة غير محكوم:** RMT تحكم فقط الأفعال المقدَّمة عبرها. أي
  وصول مباشر إلى المضيف أو عمليات خارج البوابة تبقى خارج هذا الحد.
- الموافقة تعتمد على السياسة، وليست كل الأفعال تتطلب موافقة بشرية. غياب نتيجة
  التحقق لا يعني نجاحًا مُتحقَّقًا منه. لا يوجد ضمان عام للتنفيذ مرة واحدة بالضبط.

التفاصيل: [الضمانات وحدودها](docs/RMT_GUARANTEES.md) ·
[نموذج التهديدات](docs/RMT_THREAT_MODEL.md) (بالإنجليزية).

## حوكمة أوامر Claude Code (RMT-CAP-10)

يتضمن RMT خطافًا (hook) من نوع `PreToolUse` لـ Claude Code. قبل أن تشغّل جلسة
Claude Code أمرًا يطابق قائمة صغيرة وصريحة من الأنماط الخطرة (مثل الدفع القسري،
أو `reset --hard`، أو الحذف التعاودي، أو `sudo`)، يُعلَّق الأمر بانتظار قرار
بشري، مع شرح مبني على أدلة قابلة للتحقق، وليس على رأي نموذج لغوي.

حدود يجب معرفتها:

- الخطاف **يفشل مفتوحًا (fail-open)**: إذا لم يكن الخادم متاحًا، يمر الأمر مع تحذير.
- يغطي قائمة أنماط محددة فقط، وليس كل الأوامر.
- هذه التعليقات نظام مستقل فوق النواة (above-Core)، ولا تمر عبر مسار التنفيذ
  المحكوم في النواة. لا تنتهي صلاحيتها تلقائيًا.
- الميزة معطّلة افتراضيًا (`RMT_CODING_AGENT_ENABLED=false`).

[ثبّته في مشروعك](tools/claude-code-guard/README.md) (بالإنجليزية).
السجل الكامل: [أدلة القدرات](docs/RMT_CAPABILITIES_EVIDENCE.md) (بالإنجليزية).

## أين تناسب RMT

RMT تناسب العمليات المنفصلة والقابلة للملاحظة، بحجم منخفض إلى متوسط، مع توفر
موافقة بشرية للجزء الخطر منها. لا تناسب المسارات التي تتطلب زمن استجابة أقل من
ثانية، أو الإنتاجية العالية، أو الأفعال التي لا نتيجة قابلة للملاحظة لها.

تمر كل الأفعال في دورة حياة واحدة مشتركة:
**الفهم ← القرار ← الحوكمة ← التفويض ← التنفيذ ← التحقق ← التعلّم**
(Understand → Decide → Govern → Authorize → Execute → Verify → Learn).
النواة (Core) مستقلة عن أي مجال، والمجالات تستهلك دورة الحياة دون أن تضيف
قواعدها إلى النواة.
